# デッキメモの大会結果への仮反映

## 操作

DMP大会URL（ShopID・EventID・Seq）で紐付けたデッキメモから「保存済みメモを大会結果へ仮反映」を選ぶ。入力中のメモを既存の大会メモへ保存してから、大会名・日付・3項目のキーを確認する。保存済みメモ詳細からの仮反映も可能。キーが未確定ならDMP URLを入力して大会情報を取得する必要があり、名前や2項目だけでは大会を推測しない。

大会結果ページで同じURLを入力すると、従来の公式取得に続いて保存済み公式／仮結果を読み込む。外部取得失敗は「公開状況未確認」と表示し、未公開と断定しない。

## 保存・優先順位

- 新規 `provisional_event_results` は大会につき1行。保存元アーカイブID・provider・provider大会キー・プレイヤーJSONを保持する。再反映はこの1行のUPSERTであり、元メモ・公式結果・履歴を変更しない。
- DMP IDを優先。IDなしは保存元にあるparticipant_keyを使用。名前では照合しない。同一IDでデッキが競合すれば409で反映を拒否する。
- 元アーカイブには過去ラウンドの選手も保持される。その全保存済みメンバーを反映し、同一ID／キーを1人とする。異なるproviderのIDなし選手は自動名寄せしない。現状のアーカイブ仕様は1大会1保存元で、複数providerを自動結合しない。
- 公式行がある場合、その参加者・順位のみを表示・集計する。デッキは既存履歴 > 同一DMP IDの仮デッキ > 不明。差異は表示して自動上書きしない。公式外の仮選手は公式分布には含めないがスナップショットには残る。
- 公式行がない場合は仮選手を表示し、全順位はNULL。分母は仮登録済みユニーク人数。正式参加人数とは異なる。
- 仮表示での編集は元メモを修正して再反映する。公式表示では従来の手動デッキ保存を利用できる。仮デッキの補完は表示上のものであり、履歴への自動書き込みではない。
- メモリセットで元アーカイブが削除されても仮スナップショットは残り、参照IDのみNULLとなる。大会全体の既存の明示的リセットでは大会とともに仮行も削除される（FK CASCADE）。通常の公式取得では削除しない。
