# デッキメモ同期

記入者名は `deck-memo-author` としてブラウザのlocalStorageに保存します。サーバーには送信しません。同名候補はDMP IDまたは提供元の参加者キーで区別し、選択前は卓番を確定しません。通常一覧の順番は維持し、同じ参加者オブジェクトから上部の卓番を描画します。

`GET /api/deck-memo/events?memoEventId=...` がSSE接続です。既存のShopID・EventID・SeqをDBから解決し、紐付け前のメモは独立して扱います。成功したAPI保存後、接続中のメモの保存済み状態を比較し、変化したメモの閲覧者だけに通知します。連続保存は100msにまとめ、同じメモの閲覧者間でDB取得を共有します。ハートビートは20秒、再接続間隔は3秒です。定期的なDBポーリングはありません。通知・再接続時は `GET /api/deck-memo/state` でデッキ情報だけ再取得します。

クライアント側も180msに通知を集約します。自分の保存通知は識別子で抑制します。保存中の同期は後回しにし、古い画面・保存開始前のレスポンスは適用しません。同期では行や入力要素を再生成せず、フォーカス中の選択欄はblurまで表示の更新を保留します。手動更新も同じ処理です。

## Render / Neon

既存のExpressサーバー・Neon接続を使用します。DBマイグレーションは不要です。本番DBへの変更は実行していません。

通知管理は単一Nodeプロセス内です。Renderは1インスタンスで運用してください。複数インスタンス・複数ワーカーでは別プロセスの保存通知を共有できません。その場合はRedis Pub/Subなどの共有通知基盤が必要です。停止・スリープ・再起動中は同期できませんが、EventSourceの自動再接続と接続直後の再取得で復旧します。ネットワークやスリープ時間により数秒を超える場合があります。SSEにはキャッシュ・バッファリング抑止ヘッダーを設定しています。

既存の取得ボタンは外部対戦表の取得に使います。固定の「メモを更新」は表示中の大会の保存済みデッキ情報を更新します。ブラウザテストはローカルのモックDBと分離した2つのChromeコンテキストを使用し、本番サービスには接続しません。
