# じゃんけんのあいこ履歴

最終的に出した手は既存の `rock_paper_scissors_records.hand` に保存し、あいこになった手だけを順序付きで `rps_record_ties` に保存します。既存の記録には履歴を補完せず、履歴なしとして扱います。既存のじゃんけん傾向は引き続き最終手だけを集計します。

## 保存・編集・API

- 既存の `POST /api/rps/records` に任意の `ties` 配列を追加しました。値は `rock` / `scissors` / `paper`。省略・空配列でも保存できます。
- `GET /api/rps/records?dmpId=...` または `?guestId=...` で記録を取得します。`page` は1始まり、1ページ30件です。
- `PUT /api/rps/records/:id` は既存の記録先と記録IDを照合し、最終手とあいこ履歴を更新します。記録先・作成日時は変更しません。`ties` 省略時は既存履歴を維持し、空配列で履歴を解除します。
- プレイヤー詳細・ゲスト詳細のレスポンスに `rpsTiePredictions.stages` を追加しました。従来のレスポンス項目は維持します。

親レコードとあいこ履歴は同じトランザクションで保存・更新します。名前による所有者の照合は行わず、DMP IDまたはゲストIDを使用します。

## 集計

あいこ履歴と最終手をつなげた列の、各あいこの直後の手を集計します。例：あいこ `グー → パー`、最終手 `チョキ` は、1回あいこ後にパー、2回あいこ後にチョキとして集計します。

各段階の母数は、その回数のあいこ履歴を持つ記録数です。3回を超える履歴も保存し、分析画面では1〜3回あいこ後を表示します。3回あいこ後に4回目のあいこがある場合はその手を使用します。同率最多はすべて表示し、サンプル0件は「データなし」とします。割合は小数1桁に丸めます。

## DB・Render反映手順

1. Neonのバックアップ・復旧方法を確認し、適用対象のブランチと接続先を確認してください。
2. 新コードのデプロイ前に `migrations/014_rps_ties.sql` **のみ**を対象DBへ手動で適用してください。既存テーブルは変更せず、子テーブルを追加します。再実行しても既存行は変更されません。本番で初期化や包括的なセットアップAPIを実行する必要はありません。
3. 適用完了後に通常の手順でRenderへ新コードをデプロイしてください。起動時の自動マイグレーションはありません。新しい環境変数も不要です。
4. あいこなし・ありの保存、編集、プレイヤー詳細の集計を確認してください。履歴のない旧レコードも従来どおり表示されます。

この実装作業では本番DBのSQL実行、Git commit・push、Renderデプロイは行っていません。

## ローカル検証

```sh
node --test tests/*.test.js tests/*postgres.integration.js
node tests/rps-ties.browser.cjs
node tests/rps.browser.cjs
```

DBテストは隔離したPGliteで実行します。ブラウザテストはローカルのテストサーバーを使用し、375・390・430・768・1440pxで保存、編集、再読み込み、集計、既存プレイヤー識別、横幅を確認します。
