# 卓単位のデッキ仮登録

通常行の「仮」から2件のデッキ候補を選んで保存する。通常プルダウンは従来どおり即時確定保存なので、不明な対応の入力は必ず「仮」の入力画面で行う。候補入力は未選択を拒否し、既存の確定メモは変更しない。

`015_table_deck_drafts.sql` を既存DB初期化手順に追加。新規テーブルのみで既存データの更新はない。本番DBへの適用は行っていない。

識別は `memo_event_id + round + table_no + ソート済み参加者2人`。参加者は通常メモと同じ規則（TCGは外部キー、その他はDMP ID優先、IDなしは外部キー）を利用する。卓の表示順や参加者の左右が変わっても同じ候補を参照する。卓番号が変わった場合は別の卓として扱い、以前の候補は参加者から参照可能。別ペアには卓の選択状態を付けない。

2人・一意の参加者キー・卓番号が揃わない場合、Bye、重複参加者では無効。未紐付けののじぎくメモで参加者がDBにまだ保存されていない場合は、DMP大会URLを指定して再取得する案内を表示する。名前・エントリー番号だけから参加者を推測しない。

候補は同じ回戦とそれ以前の全仮登録を表示し、元ラウンド・卓を明記する。片側確認後はもう片側の候補から使用した1件を取り除く。同一デッキ2件でも1件残る。確認は本人だけを保存する。通常保存と共通の `memo-write.js` をトランザクション内で利用し、確認済み状態も同時に保存する。「未選択」など後の通常編集に候補を再適用しない。仮登録解除は候補行だけを削除し、確定メモを変更しない。

仮候補は集計・アーカイブの確定メモクエリには参加しない。全ラウンド保存・再取得は候補テーブルを変更しない。既存SSEのスナップショット比較に候補を含め、手動更新でも選択欄を作り直さずボタン状態を更新する。

検証: Node全290件＋既存PostgreSQL統合1件（計291件）成功。PGliteの実SQLで3提供元とIDなしスガツール、再読込、片側確定、同一デッキ、複数ラウンド、解除、明示的未選択を確認。Chromeの独立したUI検証で1280/390/320px、横スクロールなし、行高55/64/64px、連動・候補表示・片側確定・残候補・解除を確認。既存workspaceブラウザテストも成功。画像は `docs/artifacts/table-drafts-*.png`。

外部本番サービス・本番DBを利用した実大会確認は未実施。候補デッキが後からマスターから削除された場合、IDで表示し確定保存を拒否するため、候補を解除して再入力する。仮候補は確定メモ用の保存アーカイブには複製せず、元の `memo_event_id` を通じて参照する。
