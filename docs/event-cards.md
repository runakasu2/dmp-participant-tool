# 大会カード

大会一覧は3列（950px以下で2列、600px以下で1列）のカード表示です。
通常クリックは既存大会詳細へ、削除選択モードでは対象選択へ進みます。
削除API・トランザクション・2重確認は変更していません。

## データ

GET /api/events に result_count、best_four（deckId / deckImageUrlを含む） を追加。
1回のSQLで全大会と順位4位以内の全員を取得します。同率も保存順位をそのまま表示します。
デッキ履歴は player_id と shop_id/event_id/seq すべてで結合し、created_at DESC NULLS LAST, id DESC の先頭1件を採用。
結果未取得と、取得済みだが4位以内のデータがない場合を区別します。

画像はdecks.image_urlに保存します。デッキ管理の代表画像欄からHTTPS URLを保存・変更し、空欄保存で解除できます。
PUT /api/decks/:id/image に {"imageUrl":"https://..."} を送信します。GET /api/decksにもimage_urlを追加。
大会カードはrank=1の使用デッキを正式名称優先、次に別名で対応させ、その画像を使います。
同率1位が複数ある場合はDMP ID順の先頭を採用します（順位自体は変更しません）。
画像未設定、デッキ未登録、対応マスターなし、結果未取得、画像読込失敗は共通背景です。
画像はブラウザから取得し、バイナリやRenderローカルへ保存しません。
名称変更では同じdecks.idの画像を維持。統合先に画像があれば維持し、なければ元の画像を引き継ぎます。
両者に異なる画像がある場合は409で統合を止めます。残す画像を決め、もう一方の画像を解除してから再実行してください。
以前のevents.image_urlは既存データを壊さないため残しますが、表示に使いません。大会単位の画像編集UI/APIは廃止しました。

## 反映

1. 変更したファイル一式をRenderへデプロイする。
2. /api/setup-db を実行し success:true を確認する。007_deck_images.sql が適用されるため、別途手動SQL実行は不要。
3. ブラウザを再読み込みして大会一覧を開く。
4. 結果取得済み/未取得の大会、同率順位、未登録デッキを確認する。
5. デッキ管理で優勝者の使用デッキに公開HTTPS画像URLを設定する。大会一覧を再取得し、対応する大会カードの背景を確認する。空欄保存で解除できる。
6. カードクリックで大会詳細へ移動することを確認する。
7. 最下部の「大会を削除」で選択モードに入り、カードクリックで選択できること、キャンセルで通常表示へ戻ることを確認する。表示確認だけなら削除確定は不要。
8. PC/スマホ幅で3列/2列/1列、長い大会名やデッキ名の折返しを確認する。

既存DBのデータは削除しません。ローカルの場合はサーバー再起動後、http://localhost:3000/api/setup-db を実行してください。

## テスト

node --test tests/*.test.js

PGliteを別途利用できる環境では tests/*postgres.integration.js を実行すると、実際のPostgreSQLエンジンで同率・大会識別・履歴重複・画像保存/解除・migration再実行と既存削除/メモ処理を確認できます。
